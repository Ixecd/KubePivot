# kp sizing

> 维度 B：单 Pod 资源优化引擎。2D 离散 DP 求解 CPU/Memory 最优配置。
> 最后更新：2026-05-08（v3.2）

---

## 概览

sizing 是 KubePivot 的资源配置推荐引擎，对应调度系统的**维度 B**（维度 A 为 BinPack 装箱调度）。核心能力：

- **2D DP 最优求解** — 80 × 128 状态空间，最小化加权资源成本 + 浪费惩罚
- **业务模板驱动** — web / batch / db / gpu / default 五种 profile，权重自适应
- **智能类型检测** — 自动分析 CPU/Mem 比例推荐 profile + 变异系数自适应权重
- **双路径数据源** — Prometheus 7 天历史 > kubectl top 瞬时采样
- **VPA 协调** — 生成 VPA recommendation YAML（只读模式），GitOps 可审计

## CLI 子命令

### recommend

计算单个 Pod 的资源建议，输出 patch YAML。

```
kp sizing recommend --pod=<name> [flags]
```

| Flag | 默认值 | 必填 | 说明 |
|---|---|---|---|
| `--pod` | — | **是** | Pod 名称 |
| `--namespace` | `default` | 否 | K8s namespace |
| `--profile` | `default` | 否 | 业务模板：`web` / `batch` / `db` / `gpu` / `default` |
| `--output` | — (stdout) | 否 | 输出 patch 文件路径 |
| `--samples` | `5` | 否 | 指标采样次数 (2-10) |
| `--interval` | `2s` | 否 | 采样间隔 |

**RBAC**：`PermSizing`

**流程**：

```
1. kubectl top pod <name> --namespace <ns> (× N 次，间隔 <interval>)
2. sizing.Compute(samples, profile)
3. sug.ToPatch(ns, name) → YAML 输出
4. 置信度 < 0.7 → 警告提示
```

**输出示例**：

```yaml
# sizing-patch: default/myapp
# profile: web, confidence: 0.85
# savings: CPU 23.5%, Mem 12.0%
# Generated by KubePivot v2.9 sizing engine
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  namespace: default
spec:
  template:
    spec:
      containers:
      - name: main
        resources:
          requests:
            cpu: "350m"
            memory: "512Mi"
          limits:
            cpu: "700m"
            memory: "1024Mi"
```

limits 固定为 requests × 2，可按 Profile 调整。

## Profile 业务模板

五种模板驱动 cost function 权重分配：

| Profile | 常量值 | 权重 (CPU, Mem, GPU) | 适用场景 |
|---|---|---|---|
| `web` | `"web"` | (0.7, 0.3, 0.0) | CPU 优先，低延迟（API / web server） |
| `batch` | `"batch"` | (0.3, 0.7, 0.0) | 内存优先，吞吐优先（Job / 批处理） |
| `db` | `"db"` | (0.3, 0.7, 0.0) | 内存优先，缓存敏感（DB / Redis） |
| `gpu` | `"gpu"` | (0.1, 0.2, 0.7) | **v3.1** GPU 优先，显存权重最高 |
| `default` | `"default"` | (0.5, 0.5, 0.0) | 均衡（未知类型兜底） |

CPU 权重高 = 倾向保守配 CPU（少浪费 CPU 资源），Memory 同理。

## 2D DP 算法详解

### 输入

- `samples []*metrics.PodMetrics` — 历史/瞬时 CPU + Memory 样本
- `profile Profile` — 业务模板（驱动权重）
- （可选）`cpuW, memW float64` — 自定义权重（`ComputeWithWeights`）

### 五步流程

#### Step 1 — 聚合指标

```
avg, std = meanStd(samples)
P95 = avg + 1.5 * std  (近似正态分布，略保守)
```

样本数 < 30 时用总体标准差（略低估真实波动），保守方向。

#### Step 2 — 离散化状态空间

| 维度 | 范围 | 步长 | 级数 |
|---|---|---|---|
| CPU | 50m ~ 4000m | 50m | 80 |
| Memory | 64Mi ~ 8Gi | 64Mi | 128 |

总状态空间：80 × 128 = **10240** 个候选 grid point。

#### Step 3 — DP 填充

对每个 state `(cpuReq, memReq)`：

```
// 稳定性约束
if req < P95 / (1 - headroom):   // headroom = 0.2
    skip                          // 不满足稳定性，跳过

// 成本函数
resourceCost = cpuReq * cpuW + memReq * memW
wasteCPU     = max(0, cpuReq - P95)
wasteMem     = max(0, memReq - P95)
wastePenalty = wasteCPU * cpuW + wasteMem * memW * 0.5
totalCost    = resourceCost + wastePenalty

// DP 递推
dp[cpuReq, memReq] = min(prev_cost, totalCost)
```

**关键设计决策**：
- 内存浪费惩罚减半（`* 0.5`）— 内存比 CPU 更具弹性，过度配置的代价更低
- headroom = 20% — 为突发留缓冲，同时避免大幅超配

#### Step 4 — 最优解选择

遍历 DP 表，选 `score` 最小的可行 state 作为推荐值。

**无可行解**：P95 超出 4000m / 8Gi 上限 → 返回 error（需手动处理）。

#### Step 5 — 置信度计算

```
confidence = min(1.0, sampleCount / 5.0)     // 基础置信度（5 样本 = 1.0）
           * (1.0 - 0.3 * max(cvCPU, cvMem)) // 波动惩罚（最多扣 30%）
                                             // clamped to [0, 1]
```

- confidence ≥ 0.7 → 可靠，可自动应用
- confidence < 0.7 → 建议人工审查
- confidence < 0.3 → 低置信度，标注警告

### 输出

```go
type Suggestion struct {
    CurrentCPU          int64   // 当前申请的 CPU (millicores)
    CurrentMem          int64   // 当前申请的内存 (bytes)
    RecommendedCPU      int64   // 推荐的 CPU (millicores)
    RecommendedMem      int64   // 推荐的内存 (bytes)
    Confidence          float64 // 0.0-1.0
    Profile             Profile
    SavingsCPU          float64 // 节省率 %（负值 = 需增加）
    SavingsMem          float64
    SampleCount         int

    // v3.1 GPU 字段
    CurrentGPUCount     int     // 当前 GPU 卡数（毫卡）
    CurrentGPUMem       int64   // 当前显存 (bytes)
    RecommendedGPUCount int     // 推荐 GPU 卡数
    RecommendedGPUMem   int64   // 推荐显存（量化到 MIG 分区）
    SavingsGPU          float64
}
```

## 智能 Profile 推荐

`RecommendProfile(samples)` 自动分析业务类型，无需用户指定 profile。

### 决策流程

```
1. 提取 CPU / Memory 均值
2. 量纲归一化：CPU(millcores) → Cores, Memory(bytes) → GiB
3. 计算比例: ratio = cpuCore / memGiB

   ratio > 2.0  → ProfileWeb    "计算密集型 (X Cores/GiB)"
   ratio < 0.5:
     ├─ mem > 1GiB → ProfileDB  "内存密集型 + 大内存 (>1GiB)"
     └─ mem ≤ 1GiB → ProfileBatch "内存密集型"
   其他          → ProfileDefault "均衡资源使用"

4. 置信度计算：
   typeConfidence = 0.7 + ratio偏移量（最多 +0.3）
   baseConf       = min(1.0, samples / 5.0)
   cvPenalty      = 1.0 - 0.3 * max(cvCPU, cvMem)
   finalConfidence = typeConfidence * baseConf * cvPenalty

5. 灰度保护：finalConfidence < 0.6 → 回退 ProfileDefault
```

### 自适应权重学习

`CalculateAdaptiveWeights(samples, baseCPU, baseMem)` 基于历史数据的 CV（变异系数）动态调整权重：

```
diff  = (cvCPU - cvMem) * 0.5
shift = clamp(diff, -0.2, +0.2)

cpuW = clamp(baseCPU + shift, 0.2, 0.8)
memW = clamp(baseMem - shift, 0.2, 0.8)
```

**逻辑**：波动越大的维度获得越高的权重 → 越保守的配置 → 减少 OOM/CPU throttle 风险。

配合 `ComputeWithWeights(ctx, samples, profile, cpuW, memW)` 使用：

```go
cpuW, memW, _, _ := sizing.CalculateAdaptiveWeights(samples, 0.5, 0.5)
sug, err := sizing.ComputeWithWeights(ctx, samples, profile, cpuW, memW)
```

## GPU Sizing（v3.1 保守模式）

`ComputeGPU(ctx, samples, profile, currentGPUCount, currentGPUMem)` — GPU 感知 sizing。

### 当前策略

- **CPU/Mem**：走 2D DP（同 `Compute`）
- **GPU**：保守不缩容，推荐值 = 当前值（`SavingsGPU = 0`）

### MIG 分区量化

`QuantizeGPUMem(rawBytes, gpuProduct)` 将显存推荐值向上取整到合法 MIG 分区：

| GPU 型号 | 合法MIG分区 |
|---|---|
| `A100-SXM4-40GB` | 5GB / 10GB / 20GB / 40GB |
| `A100-SXM4-80GB` | 10GB / 20GB / 40GB / 80GB |
| `H100-80GB` | 10GB / 20GB / 40GB / 80GB |
| 未知型号 | 不量化，返回原始值 |

## VPA 协调（只读模式）

`VPASuggestion(ns, name, sug, mode)` 生成 `autoscaling.k8s.io/v1` VPA 对象 YAML。

### 模式

| mode | 行为 |
|---|---|
| `"Off"`（默认） | 只推荐，不自动更新。安全优先 |
| `"Initial"` | 创建时应用一次 |
| `"Auto"` | 自动调整 |

**示例输出** — `configs/vpa-suggestion.yaml`：

```yaml
# vpa-suggestion: default/myapp
# Generated by KubePivot v2.9 sizing engine
# sizing profile: web, confidence: 0.85
# savings: CPU 23.5%, Mem 12.0%
# VPA mode: Off (Off=只推荐, Initial=启动时应用, Auto=自动调整)
apiVersion: "autoscaling.k8s.io/v1"
kind: VerticalPodAutoscaler
metadata:
  name: myapp-vpa
  namespace: default
spec:
  targetRef:
    apiVersion: "apps/v1"
    kind: Deployment
    name: myapp
  updatePolicy:
    updateMode: "Off"
  resourcePolicy:
    containerPolicies:
    - containerName: main
      minAllowed:
        cpu: "350m"
        memory: "512Mi"
      maxAllowed:
        cpu: "700m"
        memory: "1024Mi"
      controlledResources: ["cpu", "memory"]
      controlledValues: RequestsAndLimits
```

`WriteVPASuggestion(path, ns, name, sug, mode)` 原子写入（临时文件 + rename）。

## 部署集成

### kp deploy 自动 sizing

在 `kp deploy` 流程中，`runSizingHook()` 自动触发：

```
每个 Component（sizing.mode == "auto"）
  │
  ├── 1. Prometheus QueryRange (7d, step=15m) → 历史样本
  │      失败 → kubectl top 瞬时 5 样本
  │
  ├── 2. 可选 AutoProfile 推荐（sizing.autoProfile: true）
  │
  ├── 3. 可选自适应权重（sizing.weightLearning: true）
  │
  ├── 4. sizing.Compute(ctx, samples, profile)
  │
  ├── 5. 灰度保护：Confidence < threshold (默认 0.7) → 跳过
  │
  └── 6. 批量写入 configs/components.yaml（带注释注入）
       生成 configs/vpa-suggestion.yaml
```

10 个并发槽位（`chan struct{}` 信号量），支持大规模组件并行 sizing。

### components.yaml sizing 配置

```yaml
components:
  - name: myapp
    sizing:
      mode: auto              # "auto" | "manual"
      profile: web            # web/batch/db/gpu/default
      force: false            # 强制应用（忽略阈值）
      samples: 5              # 采样次数 (2-10)
      interval: "2s"          # 采样间隔
      window: "7d"            # Prometheus 查询窗口
      step: "15m"             # Prometheus 采样步长
      threshold: 0.7          # 灰度保护阈值
      autoProfile: false      # 自动检测 profile
      weightLearning: false   # 自适应权重学习
```

## 调度器集成

双 DP 协同中，sizing 引擎作为维度 B 接入：

```
Scheduler.Coordinate()
  │
  ├─ 1. BinPack(nodes, pods) → 收集 unassigned pods
  │
  ├─ 2. 每个 unassigned pod:
  │     ReduceCap(cap, -10%)
  │     MetricsProvider.QueryRange(7d)
  │     SizingProvider.Compute(samples, profile)  ← 调用 sizing
  │     Request = min(sizing_recommendation, cap)
  │
  └─ 3. 重新 BinPack → 循环最多 5 次
```
