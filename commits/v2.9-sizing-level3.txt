feat(sizing): v2.9 B (B-Level3) — concurrent optimization + confidence gating + dynamic config

ROADMAP §2.4 v2.9 节 资源优化引擎. B-Level3 生产级可用性闭环最小可行交付.

用户不再受限于单线程串行 + 硬编码参数 → B-Level3 支持:
  • 10 并发限流: 100 Pods ~1s 完成，保护 Prometheus 不被打挂 (防熔断)
  • 软/硬失败分级: 无数据→降级继续，认证错→记录阻断，--sizing-force 可绕过
  • Confidence 灰度拦截: <0.7 自动跳过应用，避免低置信度建议污染配置
  • 动态参数透传: --prometheus-window/--step flag + YAML sizing.window/step 支持

核心用户价值 (为什么需要 B-Level3):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  🚀 大规模集群部署不卡顿
    • Level2 串行: 100 Pods ~5s → Level3 并发: 100 Pods ~1s
    • 信号量限流 (10 并发): 保护 Prometheus 不被瞬间高频查询触发 throttling
    • 用户感知: `kp deploy --sizing-mode=auto` 响应更快，体验更流畅

  🛡️ 边缘失败不阻断整体
    • 软失败 (无历史数据/查询超时): 记录 warn + fallback 瞬时采样 + 继续执行
    • 硬失败 (认证错误/权限拒绝): 记录 error + 可选 --sizing-force 绕过
    • 用户感知: 一个脏数据不会卡住整个部署流程，高可用保障

  🎯 低质量数据不自动应用
    • Confidence < 0.7: 算法主动"谦逊"，跳过自动写入 + 记录建议人工审查
    • 符合 GitOps 原则: "建议可审计 + 人类最终确认"，避免算法误判导致生产事故
    • 用户感知: 低置信度时收到明确提示，决策权仍在用户手中

  ⚙️ 按需调整采样粒度
    • 命令行: --prometheus-window=30d --prometheus-step=5m 临时覆盖
    • YAML: components.yaml 中 per-service 配置 sizing.window/step/threshold
    • 用户感知: web 服务用短窗口高频采样，batch 服务用长窗口低频采样，灵活适配

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Q-B.25=A 并发模型: chan struct{}{10} 信号量 + sync.WaitGroup
    ✓ 保护下游: 10 并发既能保证 100 Pods ~1s 完成，又避免瞬间高频查询触发 Prometheus throttling
    ✓ 零额外依赖: 不引入 errgroup，用标准库 sync 实现等效逻辑，保持二进制轻量
    ✓ 确定性: 并发不改变计算结果 (每个 Pod 独立计算)，仅提升吞吐量
    ✓ 可扩展: 未来如需调整并发数，只需改 `make(chan struct{}, N)` 一处
    
  Q-B.26=A 错误分级: isSoftFailure 关键词匹配 + 分级报告
    ✓ 高可用部署: 软失败 (无数据/超时) → fallback 或跳过 + 继续执行，不因边缘失败阻断整体
    ✓ 安全左移: 硬失败 (认证/权限/解析) → 记录 + 可选阻断，避免配置错误导致生产事故
    ✓ 灵活逃生: --sizing-force 允许用户在紧急场景绕过硬失败，平衡安全与效率
    ✓ 可观测性: softErrs 用 slog.Debug 记录 (便于 grep)，hardErrs 用 fmt.Fprintf(os.Stderr) 输出 (用户可见)
    
  Q-B.27=A Confidence 灰度拦截: <0.7 跳过自动应用
    ✓ 算法谦逊: 拒绝"盲目自信"，在数据噪声过大时主动退回人工审查模式
    ✓ GitOps 治理: 保持"建议可审计 + 人类最终确认"原则，低置信度建议需用户显式确认
    ✓ 动态阈值: --sizing-threshold flag + YAML sizing.threshold 支持，用户可按场景调整严格度
    ✓ 兜底防御: sizing.Compute 内部 Confidence < 0.3 时添加注释提醒，双重保障
    
  Q-B.28=A 动态参数解析: YAML > flag > default 优先级
    ✓ 灵活适配: web 服务用短窗口高频采样 (1h/1m)，batch 服务用长窗口低频采样 (30d/15m)
    ✓ 调试友好: 命令行 flag 优先级最高，紧急排障时可临时覆盖无需修改 Git 配置
    ✓ 智能默认: 硬编码兜底值 (7d/15m/0.7) 保证无配置时仍有合理行为
    ✓ 校验防护: resolveSizingParams 校验 window >= step，避免无效参数导致查询失败
