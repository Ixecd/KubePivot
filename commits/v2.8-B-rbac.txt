设计核心:

    Check(ctx, user, namespace, perm) error
    Reload() error
  
  实现: FileBasedChecker (本期)
  扩展点: EtcdChecker / DBChecker (留 hook)

  7 个 Q 拍板 (5 个原 Q + 1 个补充 + 1 个 qc 神来之笔):
    Q-B1.A  members 用 email
    Q-B1.B  namespaces 用 shell glob (* / ?)
    Q-B1.C  excluded 优先级高于 permissions (单 team 内)
    Q-B2    Group 一锅端 (members 含 "group:<name>" 语法)
    Q-B3    Permission enum 风格
    Q-B4    Check 返回 error
    Q-B5    teams.yaml 缺失 → 全权限 (向后兼容, ROADMAP 一致)
    Q-B6=C  跨 team excluded 全局优先 (qc 神来之笔, 黑名单绝对优先完整实现)

  qc 拍的 2 个工程优化点 (本期实现):
    优化 1 - Glob 性能感知:
      解析 teams.yaml 时预编译 namespace 模式
      compileNsPattern 区分 exact / prefix / glob 三档
      hot path 决策树:
        exact   → ns == pattern        最快 (O(1) 比较)
        prefix  → strings.HasPrefix    快   (~80% 实际场景)
        glob    → path.Match           兜底 (慢但完整)
      实测: "kp-backend-*" 这种常见模式不调 path.Match
    
    优化 2 - O(1) 查找:
      compiledTeam.memberEmails / memberGroups / permissions / excluded
      全部 map[string]bool, 替代线性扫描

  Q-B6=C 实现 (跨 team excluded 全局优先 - 黑名单绝对优先):
    Check 内三遍扫描:
      1. 第一遍: 收集所有 (user 匹配 + ns 匹配) 的 team
      2. 第二遍: 任一匹配 team 把 perm 列入 excluded → 拒绝
      3. 第三遍: 任一匹配 team 在 permissions 含 perm 或 "*" → 允许
    
    错误信息含完整上下文:
      "用户 alice@x.com 无 controller-uninstall 权限于 namespace kp-backend-prod
       (原因: excluded-by-team:backend-team)"
    
    即使 ops-team permissions: ["*"], backend-team 的 excluded 仍优先

  Q-B5 向后兼容 (defensive):
    NewFileBasedChecker(path) 文件不存在 → 不报错, 返回空 teams checker
    Check 内 len(teams)==0 → return nil (允许)
    路径: configs/teams.yaml 用户级或集群 ConfigMap 注入

  线程安全设计:
    atomic.Pointer[[]compiledTeam] - Check 无锁读
    sync.Mutex (reloadMu) - Reload 串行化, 防并发覆盖
    Reload 失败保留旧配置 (不污染当前服务)
