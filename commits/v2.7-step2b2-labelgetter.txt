设计核心（独立接口 + 类型断言）:

  LabelGetter 是独立接口（不扩展 Detector）:
  
    type LabelGetter interface {
        GetResourceLabels(kind, name, namespace string) (map[string]string, bool)
    }
  
  为什么独立成接口而非扩展 Detector:
    - Detector 已被 KubectlDetector / mockDetector 实现
    - 扩展会强制所有实现加新方法（破坏既有 75+ 测试）
    - LabelGetter 是 InformerDetector 特有能力（cache 已有 labels）
    - 调用方用类型断言判断 (heal.go loadResourceLabels)

实现矩阵:
  InformerDetector  实现 LabelGetter  从 cache 读 Resource.Labels
  KubectlDetector   不实现           走原 kubectl 路径
  mockDetector      不实现           既有测试 0 改动

heal.go fast path（6 行）:

  if lg, ok := r.detector.(LabelGetter); ok {
      if labels, found := lg.GetResourceLabels(...); found {
          res.Labels = labels
          return true
      }
  }
  // fallback: 既有 kubectl 路径完整保留

行为分析:
  detector=KubectlDetector  → 类型断言失败 → 走原 kubectl（不变）
  detector=mockDetector     → 类型断言失败 → 走原 kubectl（既有测试不变）
  detector=InformerDetector → 类型断言成功:
    cache hit  → 直接设 res.Labels + return true（避免 kubectl fork）
    cache miss → 走原 kubectl 路径
