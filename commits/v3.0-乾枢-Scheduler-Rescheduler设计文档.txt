docs(scheduler): 乾枢脚手架跨 Chart 硬编码修复 + Scheduler/Rescheduler 设计文档

修复业务 Chart 中残留的 {{ .Release.Name }} 导致的首次部署失败，
并补充乾枢调度器与重调度器的完整设计文档。

问题:
  1. 业务 Chart 的 Deployment 模板中 ServiceAccount / InitContainer host /
     DB_HOST / DB_NAME / ETCD_ENDPOINTS 使用了 {{ .Release.Name }}，
     与 Postgres/etcd Chart 中基于项目名的静态命名不一致。
     首次部署时 Pod 因找不到 ServiceAccount 而无法创建，
     InitContainer 连不上正确的服务地址，导致部署超时失败。
  2. rollout 状态检查错误地使用了 plan.Name 而非 release 名称，
     导致 kubectl rollout status 找不到目标 Deployment，
     即使 Pod 已健康运行仍被判定失败并触发回滚。
  3. 首次部署时未自动创建 namespace，helm install 因目标命名空间缺失而失败。

修复:
  internal/scaffold/helm.go       将 Deployment 模板中所有跨 Chart 引用的
                                  {{ .Release.Name }} 替换为静态变量 name
  cmd/kp/multi_deploy.go          修正 rollout 检查使用 release 名称
  cmd/kp/deploy.go                新增 ensureNamespaceExists 幂等创建逻辑

新增:
  docs/design/scheduler.md        乾枢调度器设计文档 (BinPack / Coordinator /
                                  PlanWriter / Webhook)
  docs/design/rescheduler.md      乾枢重调度器设计文档 (周期性扫描 / 抖动检测 /
                                  多级降级 / 迁移约束)
