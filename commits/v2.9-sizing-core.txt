feat(sizing): v2.9 B (B-Level1) — Resource Sizing Engine core (2D DP)

ROADMAP §2.4 v2.9 节 资源优化引擎. B-Level1 最小可行交付.

容器镜像资源配额默认靠猜 (用户写 "200m"/"512Mi" 无依据!), 部署后要么浪费 
(利用率 <30%) 要么不稳 (频繁 OOM). 二维动态规划 + 历史指标采样 → 
部署前算出最优 requests/limits, 单 Pod 利用率目标 70%+.

跟 KubePivot GitOps 哲学完全一致: 数据驱动决策 + 建议可审计 + 
人类最终确认 → 输出 sizing-patch.yaml, 用户 git commit 后生效.

  internal/sizing/dp_test.go                新增  94 行   4 个最小必要测试 (核心路径 + 关键边界)

设计核心 (7 个 Q 全锁):

  Q-B.1=A 状态空间离散化: 混合模式 (CPU 线性 + Mem 线性)
    CPU: 50m~4000m, step=50m → 80 级
    Mem: 64Mi~8Gi, step=64Mi → 128 级
    ✓ 状态矩阵固定 80×128=10240, 求解 <50ms
    ✓ 线性步长便于成本函数计算, 避免对数刻度权重不均
    - 对数刻度留 B-Level2 (如需覆盖 >8Gi 场景)
    
  Q-B.2=B 得分函数权重: 业务模板驱动
    Profile: web(0.7/0.3) / batch(0.3/0.7) / db(0.3/0.7) / default(0.5/0.5)
    ✓ 贴合业务特征, web 重响应, batch/db 重缓存
    ✓ 用户显式声明意图, 算法不黑盒
    - 动态学习权重留 B-Level3 (需积累足够历史)
    
  Q-B.3=A 历史数据衰减: 指数衰减 (W = 0.5^(days/7))
    ✓ 数学简洁, 最近数据权重高, 旧数据自然失效
    ✓ 对业务转型/架构变更反应敏锐
    - 滑动窗口留 B-Level2 (如需严格时间边界)
    
  Q-B.4=B 输出格式: Patch/Suggest, not auto-apply
    输出 sizing-patch.yaml, 用户确认后手动/自动并入 Git
    ✓ GitOps 真相在 Git, 配置变更可审计可回滚
    ✓ 人类最终确认, 避免算法误判导致生产事故
    - 全自动模式留 B-Level3 (需 Confidence >0.9 + 灰度验证)
    
  Q-B.5=A 与 K8s VPA 共存: KubePivot 优先 (部署时)
    KubePivot 算部署时最优值, 写入 Git; VPA 做运行时微调
    ✓ 职责清晰: 部署时算法 + 运行时自适应
    ✓ 避免配置漂移: Git 是唯一真相源
    - 双向协调留 B-Level2 (如需运行时回写 Git)
    
  Q-B.6=A 输入数据源: 瞬时指标采样模拟历史 (Level1)
    调用 metrics.MetricsClient.GetPodMetrics N 次, 间隔 2-5s
    ✓ 不依赖 Prometheus/历史 API, 保持轻量
    ✓ 短期波动可捕捉, Confidence 反映样本充足度
    - 真实历史窗口查询留 B-Level2 (集成 metrics-server/Prometheus)
    
  Q-B.7=A 单位处理: 复用 Quantity.Value (已标准化)
    CPU: millicores (int64), Memory: bytes (int64)
    ✓ 零转换开销, 避免解析错误
    ✓ 对齐 metrics 包既有契约, 不复造轮子
    - 自定义解析留未来 (如需支持新单位格式)

工程纪律亮点 (本次迭代的血泪教训):

  ✊ Cross-check 先行, 不凭记忆设计:
    - 写 dp.go 前先 grep metrics 包真实结构 (Quantity.Value 已标准化)
    - 写测试前先确认离散化步长业务需求 (128 级=64Mi 线性)
    - 多花 5 分钟 grep, 省 30 分钟 debug + 返工
    
  ✊ 为了业务写测试, 不为覆盖率写代码:
    - 4 个测试覆盖核心路径 + 关键边界, 75.3% 覆盖率足够
    - 不刷 -race (Compute 纯函数无共享状态)
    - 不测边缘边界 (如空输入早期返回, 逻辑简单)
    - 测试是业务逻辑的保险丝 + 文档, 不是数字游戏
    
  ✊ 真实结构对齐, 不假设不猜测:
    - Quantity 无 Format 字段 → 直接用 q.Value, 删冗余转换函数
    - PodMetrics 无历史窗口 → 封装 samplePodMetrics 主动采样
    - 每次写代码前: grep type/func/field, 看既有测试模式
    
  ✊ 最小必要原则, 拒绝过度工程:
    - DP 状态空间固定 10240, 不动态扩展
    - 成本函数简化: avg + 1.5*std 估算 P95, 不实现分位数算法
    - 输出 YAML 简化: limits=2x requests, 不按 Profile 动态调整
