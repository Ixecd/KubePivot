InformerDetector 算法:
  1. kind 转换为 informer resource name (仅试点 Deployment)
  2. 不支持的 kind → fallback
  3. informer 未启动 → fallback (fail soft 触发后)
  4. informer.Get 找到 → return true (信任 cache)
  5. informer.Get 未找到 → fallback (cache 可能滞后，二次验证)

为什么"找到信任，没找到 fallback":
  - 信任 cache: 找到的资源大概率真存在 (Watch 已收到 ADD 事件)
  - 不信任 cache miss: cache 可能滞后 (list 未完成 / watch 延迟)
                       → fallback 到 kubectl 保证不漏查
  - 性能: 大部分查询走 cache (~50ns) 替代 kubectl fork (~100ms)
  - 一致性: 既有 v2.5/v2.6 行为完全保留 (fallback 兜底)
