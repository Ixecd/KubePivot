设计核心（auth.go - Pure Resolver）：

  K8sConfig struct - 不导出字段，外部仅通过访问器读取
    - APIServerURL() string
    - HTTPClient() *http.Client
    - Source() string  (debug 用："explicit"/"kubeconfig"/"in-cluster")
  
  resolveK8sConfig 按优先级（不做猜测式 fallback）：
    1. opts.APIServerURL 非空 → 显式 URL
       http://  → 零 TLS（Day 3 测试 / fake server）
       https:// → Go 默认 root CA 校验（不显式配 TLSConfig）
    
    2. opts.KubeConfig 非空 → kubeconfig 解析
       v2.7.0 暂不实施，返回明确 error
       留 v2.7.x（完整 contexts/users/clusters 解析 ~200 行）
    
    3. 三者都空 → in-cluster ServiceAccount 自动检测
       URL: https://kubernetes.default.svc
       Token: /var/run/secrets/kubernetes.io/serviceaccount/token
       CA:    /var/run/secrets/kubernetes.io/serviceaccount/ca.crt

安全约束（不可妥协）:
  - InsecureSkipVerify 在任何路径都不允许（强制 false）
  - TLS 1.2 minimum (in-cluster 路径)
  - Token 不进 K8sConfig 字段（仅 transport 内部持有）
  - error 信息不含 token 内容（专门 test 验证）
  - bearerAuthTransport.RoundTrip 用 req.Clone() 防 mutate 原 request
  - 自签证书场景禁止 InsecureSkipVerify，必须走路径 2/3

可测试性设计：
  readTokenFile / readCAFile 是函数变量（var）而非直接 os.ReadFile
  测试时替换为 fake，避免依赖 /var/run/secrets/... 真实路径
  生产时 var 默认值是 os.ReadFile + 标准路径

informer_impl 接入：
  NewInformer 内顺序：
    1. opts.Resource 校验
    2. opts.APIVersion 校验
    3. 默认值填充
    4. resolveK8sConfig(opts)  ← 新增
    5. opts.APIServerURL 写回标准化形式 (trim 尾部斜杠)
    6. 创建 informerImpl 用 K8sConfig.HTTPClient()
  
  Resource/APIVersion 校验在 resolveK8sConfig 之前
  → TestNewInformer_RequiresResource/APIVersion 不受影响
  → 测试场景下 Day 3 既有 14 个 informer impl test 全部走路径 1 兼容

测试覆盖（20 cases）:

  K8sConfig 访问器（1）

    PrefersExplicitURL / FallbackToKubeconfig / FallbackToInCluster
