feat(audit): 乾枢 CLI 静态审计工具 — 全命令扫描 + internal 接口清单

乾枢 (v3.0) 预备阶段工具交付。扫描 cmd/kp 下所有注册的子命令和 flag，
以及 internal/ 目录下所有公开的接口、函数、结构体，输出一份全景审计报告。
为乾枢调度器设计和全系统审查提供代码事实依据。

核心价值:
  - 一次性看清 kp 的 33 个子命令路由表（main.go switch-case 解析）
  - 提取每个命令的 flag 注册（基于 Go AST，非文本 grep）
  - 统计 internal/ 下 17 个公开接口、261 个公开函数、127 个公开结构体
  - 为乾枢调度器的 adapter.go 设计提供精确的依赖清单

变更清单:
  tools/audit/main.go                          新增 ~350 行   Go AST 静态分析工具

合计: ~350 行新代码 + 零额外依赖

设计核心 (4 个实现点):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A. 命令路由提取: 基于 main.go 的 *ast.SwitchStmt 解析
    ✓ 直接从 switch os.Args[1] 块提取 case 字符串和对应的 run* 函数
    ✓ 不依赖文本匹配，随代码重构自动更新
    ✓ 覆盖 main.go 中注册的全部 33 个一级命令

  B. Flag 注册提取: 基于 flag.NewFlagSet 的 AST 调用分析
    ✓ 解析 flag.StringVar/BoolVar/IntVar 等调用的参数
    ✓ 输出 flag 名、默认值、help 文本（当前仅部分提取，需后续完善）
    ✓ 遍历 cmd/kp 下所有非测试 .go 文件

  C. Internal 接口/函数/结构体提取: 基于 ast.TypeSpec 和 ast.FuncDecl
    ✓ 只提取公开（首字母大写）的类型和函数
    ✓ 排除 _test.go 文件，聚焦生产代码
    ✓ 输出接口的方法列表、函数的参数和返回值、结构体的字段

  D. 输出格式: 直接可读的终端文本 + 可重定向为 Markdown
    ✓ 三级标题分段：命令入口 / 子命令与 Flag / 接口 / 函数 / 结构体
    ✓ 每项含包名前缀，方便乾枢调度器定位依赖

工程纪律亮点:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✊ 静态分析优先，不手动维护命令清单
    - 避免文档和代码不同步的经典问题
    - 新增命令后只需重跑脚本，审计报告自动更新

  ✊ 零外部依赖，纯 Go 标准库
    - go/parser + go/ast + go/token 实现全部扫描逻辑
    - 与 KubePivot 的 DEPENDENCY_POLICY.md 一致

  ✊ 一次投入，多次受益
    - 乾枢调度器设计时 grep 这份输出的接口清单
    - 全系统审查时核对状态机与 reconcile 路径
    - 对外文档化 KubePivot 的系统全貌

打脸记录 (本次工具开发中的教训):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✓ 第 1 次: ast.SwitchStmt.Body 已经是 *ast.BlockStmt，无需类型断言
    根因: 凭记忆写了 if body, ok := ... 的断言模式
    修复: 直接使用 stmt.Body.List，去掉多余的类型断言

  ✓ 第 2 次: flag 提取逻辑覆盖不全，部分自定义 flagSet 的调用模式未识别
    根因: 项目中使用多种 flag 注册方式（flag.StringVar / flags.NewFlagSet）
    对策: 当前先覆盖 flag.StringVar 等标准调用，后续完善对其他模式的支持
