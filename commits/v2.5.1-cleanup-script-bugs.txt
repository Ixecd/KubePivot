fix(benchmark): cleanup.sh + setup.sh 显示 bug + HANDOFF 3.7 扩展

bug 1: cleanup.sh 变量定界（中文标点紧贴变量名）
  原：  log "项目数 $total >= $LARGE_THRESHOLD，先停 controller"
  bash 解析：把 "LARGE_THRESHOLD，先停" 当成单个变量名
  → 输出 "项目数 50 >= " 后面变成 "??"
  
  修：用 ${} 显式定界变量名
  log "项目数 ${total} >= ${LARGE_THRESHOLD}，先停 controller"
  
  共 9 处变量定界修复（覆盖 Phase 1-5 的所有 log）

bug 2: setup.sh 写死的 "10 个 mock namespace"
  原：  log "批量生成 10 个 mock namespace + 资源"
  PROJECT_COUNT=50 时仍显示 "10 个"
  
  修：log "批量生成 ${#PROJECTS[@]} 个 mock namespace"
  动态读 PROJECTS 数组实际长度

HANDOFF 3.7 扩展：
  原 3.7 只覆盖了 set -e/-u 的陷阱
  今天上午两次踩"中文标点紧贴变量名"的坑（同根问题不同表现）
  扩展加入"衍生陷阱"小节，用反例 + 正例 + 实践规范说清楚
  
  规范：default 都用 ${var} 风格，避免心智负担

测试通过：
  PROJECT_COUNT=50 setup.sh 显示 "批量生成 50 个"
  PROJECT_COUNT=50 cleanup.sh 显示完整进度数字 + 控制器副本数

工程意义：
  这是把"重复踩坑"的代价转化成"长期资产"
  下次写 bash 脚本看到 HANDOFF 3.7 就不会再踩
