设计核心:

  ResolveActor 三档降级 (Q-B7.1=A):
    1. SSO email      读 ~/.kp/credentials/default.yaml → <provider>.yaml → email
    2. USER@host      os.Getenv("USER") + "@" + hostname  
    3. anonymous@host
    
    永不返回空字符串 (audit Actor 必须有值)
    永不 panic (audit 是侧支, 不能因解析失败影响主命令)
    文件 I/O 失败静默降级 (静默 = 不 slog, 不污染日志)
    
    ResolveControllerActor: controller 端固定标识符
      kubepivot-controller@<POD_NAME 或 hostname>

  Record 不阻断主流程 (Q-B7.2=B):
    Record(source, action, actor, resource, ns, outcome, reason)
    内部调 Write, 失败只 slog.Warn, 永不返回 error
    调用方典型 defer 模式, 无需 if err != nil
    
    设计权衡: 可用性 > 可观测性
    审计是侧支流程, 不能因 disk full / permission denied 阻断 deploy

  按 source 分文件 (Q-B7.3=A):
    ~/.kp/audit/deploy.jsonl
    ~/.kp/audit/sandbox.jsonl
    ~/.kp/audit/secret.jsonl     (跟既有保持一致)
    ~/.kp/audit/drift.jsonl
    ~/.kp/audit/controller.jsonl
    ~/.kp/audit/rollback.jsonl
    
    优势: kp audit --source 极速过滤 + 字段 schema 可独立演进

  本期不做 (Q-B7.5=A KISS):
    - 文件 rotation (用 logrotate 标准方案)
    - immutable WORM 存储 (ROADMAP F 排除)
    - 远程聚合 (Loki/ES)

8 个 Q 拍板:
  Q-B7.1=A  Actor 优先级 SSO > USER > Anonymous (柔性降级)
  Q-B7.2=B  写入失败不阻断 (可用性优先)
  Q-B7.3=A  按 source 分文件 (跟 secret.jsonl 既有约定)
  Q-B7.4=B  本期 6+1 critical 命令接入 (留给 B.7.2)
  Q-B7.5=A  本期不做 rotation (KISS)
  Q-B7.6=A  state.History 加 Actor 字段留给 B.7.2 (本期不动)

  + 实施期补充 2 个隐藏 Q (代码评审过程涌现):
  Q-B7.7    读取端旧数据兼容: collectSecret/DriftAudit 优先读 raw["actor"]
            没有则 fallback 到既有 hardcoded ("kp-cli" / "kubepivot-controller")
            理由: ~/.kp/audit/secret.jsonl 历史数据没 actor 字段, 不能让旧数据消失
  Q-B7.8    写入端字段名一致性: secret.jsonl 用 "ts" / drift etcd 用 "ts"
            AuditEvent 用 "timestamp" — 三个命名不统一是历史债, 本期不修
            (改造影响面太大, 留 v2.8.x 文档化)
