feat(supply-chain): v2.8 H (H-Level1) — kp supply-chain verify + cosign CLI wrapper

ROADMAP §2.4 H 节 供应链安全集成. H-Level1 最小可行交付.

容器镜像默认无签名验证 (任何 registry 都可 push 任意 tag!), 部署未签名镜像 = 
供应链攻击敞口. cosign (Sigstore) 用公钥签名 → 镜像即使被篡改也无法通过验证
(私钥永远不出 CI 环境). verify 通过后才能 kp deploy.

跟 KubePivot GitOps 哲学完全一致: 镜像签名 → 部署前校验 → 拒绝未签名镜像
→ 确保集群只运行可信工件.

  Q-H.3=A --output text + json 双模式:
    不指定 → text (人类可读, ✓ Verified)
    指定 --output json → 结构化输出 (CI/CD jq 友好)
    用户学习成本 0, 跟既有 kp scan --output 风格自然衔接
    
  Q-H.4=A 退出码语义 0/1/2:
    0 = 验证成功 (签名匹配)
    1 = 业务失败 (签名不匹配, 可被 CI 捕获)
    2 = 工具错误 (cosign 未安装/网络超时)
    对齐 Unix 惯例 + 方便流水线逻辑判断
    
  Q-H.5=A 30s timeout 防挂起:
    exec.CommandContext 硬编码 30s 超时
    防止 Registry 网络问题导致 CLI 永久阻塞
    Level1 简单优先, --timeout flag 留 H-Level2
    
  Q-H.6=A 单元测试 + exec 注入钩子:
    execCommandFunc 函数变量让 6 cases 全 mock
    CI 不依赖 cosign 二进制
    真集成测试留给用户实操验证
    
  Q-H.7=A 错误消息提取 + 友好提示:
    区分 "签名不匹配" (业务失败) vs "cosign 未找到" (工具故障)
    extractCosignError 优先匹配已知模式 + 回退解析
    用户永远看到人类可读的错误, 不是原始 stderr

实施流程 (跟 cosign 官方推荐 100% 一致):

  Step 1: CI 用 cosign sign --key cosign.key registry.io/img:v1
  → 镜像附带签名 (公钥验证)

  Step 2: 用户本地运行:
    kp supply-chain verify registry.io/img:v1 --key cosign.pub
  → 内部调用: cosign verify --key cosign.pub --output json registry.io/img:v1

  Step 3: 解析 JSON 输出 → 结构化 Result
  → 输出: ✓ registry.io/img:v1 verified (sha256:a1b2c3...)

  Step 4: 验证通过 → kp deploy (或集成到 CI 流水线)
  → 验证失败 → os.Exit(1) + 友好错误消息
