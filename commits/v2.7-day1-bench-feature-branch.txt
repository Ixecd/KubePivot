实施迭代：
  v1: 初版 SkeletonCache 实现 (immutable snapshot + atomic.Value)
       List(ns) 全表扫描 → 9700ns（差）
       ColdStart 10000 → 1580ms / 2370MB (O(N²) 拷贝灾难)
  v2: 修复（fix_hotcache patch）
       SkeletonCache 改用 ns 二级索引 (map[ns]map[name]*Skeleton)
       新增 PutBulk 批量写入（避免 O(N²)）
       List(ns) 9700ns → 147ns (66x 提升)
       ColdStart 10000 1580ms → 341ms (4.6x 提升)
       内存放大率保持 ~1.65x

修复后核心数据（vs client-go，Apple M4 / Go 1.25）：
  Cache Get:           14.5ns vs 45ns        (3.1x 时间, 6x 内存)
  Cache List (ns):     147ns vs 6800ns       (46x 时间, 100x 内存)
  Cache ListAll:       7500ns vs 7300ns      (持平时间, 2x 内存)
  ColdStart 1000:      35ms vs 61ms          (1.8x 时间, 8.5x 内存)
  ColdStart 10000:     341ms vs 645ms        (1.9x 时间, 8.6x 内存)
  ParseOnly:           35μs vs 60μs          (1.7x 时间, 8.7x 内存)
  内存放大率 (1w obj): 1.65x vs 4.69x        (2.84x 优势)

工程伦理：
  - 不藏数据
  - 业务场景大胜，全量遍历持平，内存全场胜
  - 测试限制诚实标注（fake 数据 / macOS heap 替代 RSS / Bench 3 缺）
