docs(design): Informer KV Cache 设计 — 从 Skeleton 到完整资源对象

当前 Informer Watch Pod/Node 但只存 Skeleton 元数据，scheduler 每 5min
重复打 kubectl 全量查询同一批数据——两套数据通路各跑各的，Watch 流浪费。

本设计将 Informer Hot 层从 Skeleton cache 升级为 KV cache（PodCache +
NodeCache），通过 InformerAdapter 实现 PodLister/NodeLister 接口，
scheduler 从 kubectlAdapter 切换到内存 O(1) 读。同时为池化层提供
高速数据通路（池化需频繁扫全集群算碎片率）。

KV Cache 核心设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  数据结构:
    PodCache: map[string]*PodInfo + byNode 二级索引
    NodeCache: map[string]*NodeInfo
    "完整" = 调度字段（CPU/Mem/GPU/Phase/Labels），非 K8s 全字段
    字段裁剪: managedFields/ownerReferences/conditions 全剔除
    CPU 用 int32 压内存（limits.go 单测防溢出）

  写入优化:
    PutBulk 双缓冲: 内存构造 newMap → 指针交换（持锁 341ms → 纳秒）
    MODIFIED Fast Pre-check: 调度字段无变化直接 return，跳写锁 + 通知
    atomicUpdate() 封装: pods + byNode 必须在同一闭包内更新
    410 Gone: 先建完整新快照，再原子替换（调度器读不到残缺快照）
    Go map 内存压缩: fragmentation_ratio > 3 触发 PutBulk 强制压缩

  读取路径:
    InformerAdapter 实现 PodLister/NodeLister
    影子降级: cache.ready==false → 透传 kubectlAdapter

  Subscribe 事件驱动:
    CacheSubscriber 接口 + CacheChangeEvent
    30s debounce + BulkResync jitter (0-5s)
    Keys 去重 Set 语义 + 以 cache 当前态为准

  监控指标:
    pods_total / nodes_total / hit_total / stale_seconds (Heartbeat)
    / watch_restarts / bulk_insert_ms / fragmentation_ratio
