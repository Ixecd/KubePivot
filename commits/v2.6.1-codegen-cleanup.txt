修复 1: codegen 输出文件名 dir 模式 bug

  现象:
    cd internal/code
    go run ../../tools/codegen -type=ErrorCode .
    → 产物文件名 ._generated.go (不是 code_generated.go)

  根因 (codegen.go line ~155):
    if len(flag.Args()) == 1 {
        baseName = ... TrimSuffix(flag.Args()[0], ".go") ...
    }
    
    设计意图: 用户传单个 .go 文件时，用文件名当 basename
    实际行为: 单个目录 (".") 也进 if 分支
              filepath.Base(".") = "."
              → baseName = "._generated.go"

  修法: 加 !isDirectory 守卫，复用既有 helper

    -    if len(flag.Args()) == 1 {
    +    if len(flag.Args()) == 1 && !isDirectory(flag.Args()[0]) {

  3 场景走读:
    单目录 ["."]            → 不进 if，用 dir basename = code_generated.go ✓
    单文件 ["error.go"]     → 进 if，用 file basename = error_generated.go ✓
    多文件 ["a.go","b.go"]  → 不进 if (len≠1)，用 dir basename ✓

  v2.6.0 工程债澄清:
    HANDOFF/TODO 当时归因为"codegen 不支持多 const block"
    实测多 const block 完全 work (5 个 ErrRoute* 都正确识别)
    根因实际是输出文件名 bug，错误归因导致手工补救路径错位
    本修复同时关闭这条历史误判

修复 2: codegen -doc 模式默认输出 .md 后缀

  现象:
    go run ../../tools/codegen -type=ErrorCode -doc .
    → markdown 内容写进了 code_generated.go (Go 源文件被污染)
    → 下次 make dev 直接炸

  根因:
    -doc 模式跟非 -doc 共用默认 baseName = <dir>_generated.go
    内容是 markdown 但文件后缀是 .go

  修法: -doc 时默认后缀切到 .md

    +    ext := "_generated.go"
    +    if *doc {
    +        ext = "_generated.md"
    +    }

  3 场景走读:
    codegen .                → code_generated.go ✓ (不变)
    codegen -doc .           → code_generated.md ✓ (修复，不再污染 .go)
    codegen -doc -output X.md . → X.md ✓ (不变，外层 if outputName=="" 不进)

  设计边界:
    codegen 不内置"项目级 doc 路径约定"
    -doc 产物落在源码包内，由调用方 (Makefile/CI/手动) 决定归宿
    -doc -output <path> 仍是项目级使用的推荐姿势
