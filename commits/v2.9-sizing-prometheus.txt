feat(sizing): v2.9 B (B-Level2) — Prometheus integration + batch atomic write + business-driven tests

ROADMAP §2.4 v2.9 节 资源优化引擎. B-Level2 生产可用性升级最小可行交付.

用户不再依赖瞬时采样 (5 次/2s) → B-Level2 支持 Prometheus 历史查询 (7d/15min) + 
fallback 瞬时采样 + 全量 Pod 优化 + 批量原子写入 → 
数据更准 (历史趋势) + 覆盖更全 (多 Pod) + 写入更安全 (原子性) + 测试更可靠 (业务语义).

核心用户价值:
  - 部署前自动计算最优资源，单 Pod 利用率目标 70%+
  - Prometheus 历史数据 → 更准确的 P95 估算 → 更少误判
  - 全量遍历 → 多服务项目一次部署全部优化
  - 批量原子写入 → 避免"后写覆盖先写"的竞态
  - 业务语义测试 → 验证值不验证格式，测试更稳定

    - Level3 可评估是否引入 prometheus/common (如需高级功能)
    
  Q-B.19=A 配置优先级: 命令行 flag > components.yaml > 默认
    ✓ 对齐既有模式 (env > yaml > default)，用户心智统一
    ✓ CI/CD 场景可通过 --sizing-mode=auto 强制覆盖开发者本地配置
    ✓ 显式 > 隐式，避免"魔法配置"导致的行为不确定
    
  Q-B.20=A 全量优化并发: Level2 串行遍历
    ✓ 稳健先行: 100 Pods 串行 ~5s，CLI 交互可接受
    ✓ 先跑通状态转移逻辑，Level3 再引入 errgroup 限流
    ✓ 避免过早并发复杂化 (竞态/超时/重试/限流)
    
  Q-B.21=A 采样策略 Fallback: Prometheus → 瞬时采样 → 失败
    ✓ 数据分级: 真实历史更准，但兜底保证可用性
    ✓ metrics-server 可能未部署 → 瞬时采样保底
    ✓ 用户无感知降级，部署流程不中断
    
  Q-B.22=A 批量写入策略: 收集修改 → 一次性原子写入
    ✓ 避免多次读写竞争: 每个 Pod 独立写入可能覆盖前一个修改
    ✓ 原子性保证: 临时文件 + os.Rename，写入中断不损坏文件
    ✓ 幂等性: 空更新列表 → 文件不变 + 无错误
    
  Q-B.23=A 测试策略: 验证业务语义，不验证序列化格式
    ✓ 解析 YAML 后断言字段值 (c.CPU == "500m")，不匹配原始字符串
    ✓ 4 个用例覆盖: 成功/部分成功/非法 YAML/幂等性，最小必要
    ✓ 测试是保险丝 + 文档，不是序列化格式的校验器
    
  Q-B.24=A 函数职责拆分: compute / write / orchestrate 分离
    ✓ computeSizingForPod: 只计算，返回 *Suggestion，不写文件
    ✓ updateComponentsSizingBatch: 只写入，批量原子更新，不计算
    ✓ runSizingHook: 编排流程，解析配置 + 调用计算 + 调用写入
    ✓ 单一职责，便于测试 + 复用 + 未来扩展

    - errgroup 并发优化: 100 Pods 从 ~5s → ~1s (限流 10 并发)
    - Confidence 灰度策略: <0.7 不自动应用，记录日志 + 人工审查
    - 动态配置解析: components.yaml sizing 字段全量支持 (mode/profile/samples/interval)
    - Prometheus 查询参数可配置: --prometheus-window=30d --prometheus-step=5m
    
  B-Level3 (可观测性):
    - metrics 暴露: kubepivot_sizing_compute_duration_seconds, kubepivot_sizing_suggestions_applied_total
    - 日志增强: sizing 决策路径记录 (P95 估算/离散化级别/成本计算)
    - 调试模式: --sizing-debug 输出完整搜索空间 + 决策理由
    
  B-Level3 (安全加固):
    - 原子写入升级: 备份 + 回滚 (components.yaml.bak)
    - 权限校验: 写 components.yaml 前检查文件权限 + 所属用户
    - 并发锁: flock 防止多进程同时写入同一文件
    
  B-Level4 (智能升级):
    - 动态权重学习: 基于历史利用率自动调整 cpuWeight/memWeight

    - 与 K8s VPA 双向协调: 部署时建议 + 运行时反馈闭环
