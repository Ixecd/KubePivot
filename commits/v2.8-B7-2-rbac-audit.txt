设计核心:

  1 行接入模式 (Q-B7.13=A 简化):
    每个 run 函数加 1 行:
      mustCheck(audit.ResolveActor(), <namespace>, rbac.<Permission>)
    
    拒绝 → mustCheck 内部:
      1. audit.Record source=rbac action=rbac.denied actor outcome=denied reason
      2. P.Fail + 错误提示 + 联系管理员 hint
      3. os.Exit(1)
    
    通过 → 主逻辑继续, success audit 走既有状态机路径
    
    KISS 原则: 跨 7 个 run 函数零样板代码差异, 复用最大化

  Q-B7.10=C 拍板 - rbac_helper.go 封装:
    sync.Once lazy load (整个进程一次 teams.yaml 解析)
    rbacChecker 单例缓存
    ResetRBACCheckerForTest() 测试时重置 cache
    
  Q-B7.11=C 拍板 - 路径优先级:
    1. <projectRoot>/configs/teams.yaml      项目级 (推荐)
    2. ~/.kp/teams.yaml                      用户级 (本地测试)
    3. 都没有 → empty checker (Q-B5 全权限, 向后兼容)
    
    跟 KPEnv 同模式 (configs/project.env + ~/.kp/envs/)

  Q-B7.12=A 拍板 - controller namespace 字段:
    runControllerInstall / runControllerUninstall 用 *namespace 字面值
    诚实反映实际操作 ns ("kubepivot-system" 默认)
    teams.yaml 可通过 exact / prefix 模式精准控制

  Q-B7.13=A 拍板 (隐藏 Q, 实施期涌现) - success audit 跟踪策略:
    选 A 简化方案: 不写 defer success audit, 只写 denied audit
    理由:
      1. denied 是治理核心 (qc 的 "老板想知道是谁点的" 洞察)
      2. success audit 已通过既有状态机间接 (collectDeployAudit 从 etcd 读)
      3. 避免每次 deploy 写一条 jsonl 日志噪音
      4. 7 个 run 函数所有 return 点跟踪 outcome 复杂度高
    
    选 B 完整方案 scope 翻倍且大部分价值在 B.7.1 已通过状态机 actor 升级实现

  Q-B7.9=A 拍板 - 严格 7 HIGH 接入:
    HIGH 名单 (本期):
      runDeploy             → PermDeploy
      runResume             → PermDeploy   (跟 deploy 同权限)
      runRollback           → PermRollback
      runSandboxStart       → PermSandbox
      runDown               → PermRollback (销毁性, 跟 rollback 同级)
      runControllerInstall  → PermControllerInstall
      runControllerUninstall → PermControllerUninstall
    
    MEDIUM (后续 v2.8.x 持续补):
      runResume / runSandboxStatus / runSandboxUnlock /
      runControllerStatus / runControllerEnroll / runControllerUnenroll
    
    LOW (本期不接入):
      runStatus / runDiff / runDoctor* (只读) /
      runMigrate* / runSecret* (复杂, 单独评估)

3 入口模式适配:
  
  模式 1 (deploy / resume): 
    cfg := &deployConfig{} + flags.StringVar(&cfg.namespace, ...)
    patch 锚点: projectName 解析后 → mustCheck 用 cfg.namespace
  
  模式 2 (rollback / down / sandbox-start):
    namespace := flags.String(...) + cfg := &deployConfig{namespace: *namespace}
    patch 锚点: 同模式 1 (cfg.namespace 已可用)

    无 cfg / 无 projectName
    patch 锚点: flags.Parse 后 → mustCheck 用 *namespace
    audit resource 字段固定 "kubepivot-controller"
