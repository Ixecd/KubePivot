feat(sizing): v2.9 B (B-Level4) — auto profile recommendation + explainable AI + conservative gating

ROADMAP §2.4 v2.9 节 资源优化引擎. B-Level4 智能推荐最小可行交付.

用户不再手动声明 profile=web/batch/db → B-Level4 支持:
  • 自动推荐: 分析 CPU/Mem 比值 + 内存绝对值 → 智能建议业务模板
  • 可解释性: 返回 reason 字符串 ("compute-intensive pattern (CPU/Mem ratio=2.34 > 2.0)")
  • 保守兜底: 置信度 <0.6 → 降级 default，避免低质量推荐污染配置
  • 渐进启用: auto_profile 默认 false，用户显式开启，保持向后兼容

  🎯 降低使用门槛，新用户零学习成本
    • 无需记忆 profile 语义 (web=CPU 优先，batch=Mem 优先)
    • 算法自动分析历史指标 → 推荐最匹配的业务模板
    • 用户感知: `kp deploy --sizing-mode=auto` 自动适配服务特征

  🔍 决策透明可解释，拒绝黑盒算法
    • 每条推荐附带 reason 字段: "compute-intensive pattern (ratio=2.34)"
    • 用户可知"为什么推荐 web"，便于审计 + 调试
    • 符合云原生可观测性原则: 算法决策路径可追溯

  🛡️ 保守兜底保证质量，避免算法误判
    • 置信度 <0.6 → 自动降级为 ProfileDefault
    • 样本不足 (<3) → 返回默认 + 低置信度提示
    • 用户感知: 低质量数据不会导致错误推荐，安全左移

  ⚙️ 渐进式启用，零行为突变
    • auto_profile 默认 false，老用户升级无感知
    • 新用户显式开启: components.yaml 加 `auto_profile: true`
    • 符合语义化版本原则: 新功能不破坏既有行为

    • RecommendProfile 函数: 基于资源比值规则匹配 (CPU/Mem ratio)
      - ratio > 2.0 → ProfileWeb (compute-intensive)
      - ratio < 0.5 + Mem >1Gi → ProfileDB (memory-intensive + cache)
      - ratio < 0.5 + Mem <1Gi → ProfileBatch (memory-intensive)
      - 0.5 <= ratio <= 2.0 → ProfileDefault (balanced)
    • 置信度计算: 样本量调整 (+0.2 for >=10 samples) + 偏离度调整
    • 保守兜底: confidence < 0.6 → 降级 default + 记录 reason
    • GenerateExplainComment 辅助函数: 生成可解释性注释模板
