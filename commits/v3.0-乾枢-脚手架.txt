feat(scaffold): v3.0 安全基线脚手架 — Secret 管理 + RBAC 闭环 + 网络隔离 + 只读根文件系统

乾枢 v3.0 脚手架模板安全加固。将 KubePivot 生成的业务服务 Helm chart 从
"Demo 级"提升至"生产就绪"级别，默认遵循最小权限、防御深度和
零信任安全原则。

核心用户价值:
  - 数据库密码通过 Secret 管理，不再硬编码在 values.yaml 或 Deployment 中
  - RBAC 三元组 (SA + Role + RoleBinding) 完整生成，默认全部拒绝
  - 数据库中间件 (Postgres/etcd) 默认启用 NetworkPolicy，仅允许业务 Pod 访问
  - 容器根文件系统默认只读，遵循 CIS Kubernetes 安全基准
  - InitContainer 增加超时重试逻辑，避免永久阻塞

变更:
  internal/scaffold/helm.go                  重构 ~300 行   安全基线模板全面升级

合计: ~300 行重构 + 0 额外依赖

设计核心 (6 个决策点全锁):

  Q-Scaffold.1=A Secret 单一事实来源: Postgres Chart 负责生成
    ✓ Secret 仅在 Postgres 独立 Chart 中定义和管理
    ✓ 业务 Chart 通过 secretKeyRef 消费，不重复创建同名资源
    ✓ 遵循 "Don't Repeat Yourself" 原则，避免部署冲突

  Q-Scaffold.2=A 数据库连接变量解耦: 拆分为独立环境变量
    ✓ DB_USER / DB_PASSWORD / DB_HOST / DB_NAME / DB_SSLMODE
    ✓ 密码通过 Secret 注入，符合 12-Factor App 原则
    ✓ 移除硬编码的 DATABASE_URL，避免配置漂移

  Q-Scaffold.3=A RBAC 默认拒绝: rbac.create 默认为 false
    ✓ ServiceAccount 已绑定但 automountServiceAccountToken 默认关闭
    ✓ Role 和 RoleBinding 模板提供带注释的示例，按需开启
    ✓ 与 v2.8 RBAC 的 teams.yaml 逻辑对称: "默认全拒绝，显式放行"

  Q-Scaffold.4=A 网络策略最小化: Postgres/etcd 仅允许业务 Pod 访问
    ✓ 通过 podSelector 匹配 app: %s 标签精确控制
    ✓ 与业务 Chart 的 NetworkPolicy (namespace 级别隔离) 形成纵深防御
    ✓ etct 保持监听 0.0.0.0 以保证 Service 可达性

  Q-Scaffold.5=A 容器安全上下文加固: readOnlyRootFilesystem 默认 true
    ✓ 容器根文件系统不可写入，大幅提高入侵难度
    ✓ runAsNonRoot + allowPrivilegeEscalation: false + drop ALL capabilities
    ✓ 符合 CIS Kubernetes Benchmark 推荐配置

  Q-Scaffold.6=A InitContainer 超时保护: 避免永久阻塞
    ✓ wait-postgres 最多重试 30 次 (60s)
    ✓ wait-etcd 最多重试 60 次 (120s)
    ✓ 超时后 exit 1 触发 Pod 重启，故障可见
