ROADMAP §2.4 H 节 供应链安全集成. H-Level2 最小可行交付.

容器镜像默认无成分清单 (任何镜像都可能含未知依赖!), 部署无 SBOM 的镜像 = 
合规审计盲区 + 漏洞追溯困难. syft (Anchore) 生成标准化物料清单 → 
镜像成分透明化, 支持 CycloneDX/SPDX 双标准, 为后续漏洞关联/许可证合规打底.

跟 KubePivot GitOps 哲学完全一致: 镜像扫描 → 生成结构化 SBOM → 
git commit configs/sboms/ → 后续 pipeline 自动关联 CVE/许可证策略.

实施流程 (跟 syft 官方推荐 100% 一致):

  Step 1: 用户运行:
    kp supply-chain sbom registry.io/app:v1.2.3
  → 内部调用: syft registry.io/app:v1.2.3 -o cyclonedx-json -q

  Step 2: 解析输出 → SBOMResult 结构化封装
  → 可选: 提取 package_count 等元数据 (增强体验)

  Step 3: 输出:
    - 默认: stdout (可 pipe: | jq '.components | length')
    - --output sbom.json: 写文件 (自动创建父目录)

  Step 4: 用户 git add configs/sboms/app-v1.2.3.sbom.json
  Step 5: 后续 pipeline 自动关联:
    - grype sbom.json → CVE 扫描
    - license-checker → 许可证合规
    - dependency-track → 组件依赖图谱

工程纪律亮点:
  - 0 第三方 Go SDK (无 github.com/anchore/syft, 纯 CLI wrapper)
  - 复用既有 exec.CommandContext 模式 (跟 kubectl/helm/trivy/cosign 一致)
  - execCommandFunc 包级钩子, syft/cosign 测试统一注入 (避免重复代码)
  - SBOMResult 扁平化设计 (方便 JSON 序列化 + 后续关联分析)

  - 防御性解析: 字符串计数替代 JSON 解析 (Level2 保持轻量, 避免依赖膨胀)
