feat(supply-chain): v2.8 H (H-Level3) — declarative policy + deploy pre-check hook

ROADMAP §2.4 H 节 供应链安全集成. H-Level3 最小可行交付.

容器镜像默认无策略约束 (任何注册表/签名状态都可部署!), 部署无治理的镜像 = 
供应链攻击敞口 + 合规审计失败. 声明式策略 (Declarative Policy) + 部署前拦截 → 
确保集群只运行符合组织策略的可信工件, 为企业级 GitOps 打底.

跟 KubePivot GitOps 哲学完全一致: 策略即代码 (resources.yaml / project.env) → 
部署前自动校验 → 违反即阻断 + 清晰错误 → 审计日志可追溯.

实施流程 (跟企业级策略治理最佳实践 100% 一致):

  Step 1: 配置策略 (三选一或组合):
    - project.env: SUPPLY_CHAIN_ENFORCE=true, REGISTRY_DENY=docker.io/malicious
    - resources.yaml: per-resource supply-chain 覆盖
    - CI/CD: KP_SUPPLY_CHAIN_ENFORCE=true 环境变量注入

  Step 2: 用户运行部署:
    kp deploy --components configs/components.yaml

  Step 3: 内部流程:
    → 解析 plan, 提取待验证镜像列表
    → 加载全局策略 + 合并 per-resource 覆盖
    → 串行验证每个镜像 (registry → signature → SBOM → CVE)
    → 缓存命中则跳过重复验证 (5min TTL)

  Step 4: 验证结果:
    - 全部通过: 继续执行部署, 日志: "✓ Supply chain policy passed for N images"
    - 任一失败: 阻断部署 + 清晰错误:
        ✗ Supply chain policy check failed
          Details: image "docker.io/malicious:latest": registry "docker.io/malicious" is explicitly denied
        💡 Use --skip-supply-chain to bypass (emergency only)

  Step 5: 紧急绕过 (可选):
    kp deploy --skip-supply-chain  # 仅用于调试/回滚, 生产环境慎用

工程纪律亮点:
  - 0 第三方策略引擎 (无 OPA/CEL, 纯 Go 实现, 避免依赖膨胀)
  - 复用既有 exec.CommandContext 模式 (跟 cosign/syft wrapper 一致)
  - execCommandFunc 包级钩子, 所有外部 CLI 测试统一注入 (避免重复代码)
  - SupplyChainConfig 扁平化设计 (方便 YAML 解析 + JSON 序列化 + 后续扩展)
  - 纯函数隔离: extractRegistry / contains / truncateOutput 独立测试
  - 防御性匹配: 注册表策略用「含/判断维度」, 避免过度解析 + 向后兼容
  - 缓存设计: sync.RWMutex + 后台清理协程, 避免 goroutine leak + 竞态条件
